# Privateer first milestone

Fresh Rust project, not a renamed First Mate or Corsair checkout. The live fleet is not a deployment target. Keep source generic and all personal integration choices in optional plugins and local configuration. No credentials in source, messages, fixtures, command arguments, or exported evidence.

## Interfaces for this build

Library modules: `store`, `core`, `jobs`, `plugins`, `peers`. Error type is `anyhow::Result`. JSON is `serde_json::Value`. `Store::open(home: &Path) -> Result<Store>`; `Store::connection(&self) -> &rusqlite::Connection`; `Store::home(&self) -> &Path`; `Store::audit(kind: &str, payload: &Value) -> Result<i64>`; `Store::authorize(task_id: &str, action: &str) -> Result<Value>` returns effective charter with absolute `repo`, actions, resource/profile fields; `Store::task(task_id: &str) -> Result<Value>` returns task including `owner`, `charter_id`, `status`; `Store::now_ms() -> i64`.

Each module exports `dispatch(store: &mut Store, command: &str, args: Value) -> Result<Value>`, using fully qualified commands. Unknown commands must return an error. Core owns root `dispatch` router. For command-line inputs, see the [README](../README.md#general-runtime-and-optional-integrations). `rpc` serves JSON lines `{ "id": "...", "command": "task.list", "args": {} }`, returns `{ "id": "...", "ok": true, "result": ... }` or `{ "id": "...", "ok": false, "error": "..." }`. One JSON response per request; diagnostics to stderr. CLI special internal `_job-supervise JOB_ID` is owned by jobs module. Root main calls `jobs::supervise(&mut store, job_id)`.

Core owns `src/store.rs`, `src/core.rs`, `src/lib.rs`, `src/main.rs`, core integration tests, task/charter/event/decision/delivery commands and common schema. Jobs owns `src/jobs.rs` and its tests, including SQL tables initialized by `jobs::init(&Store) -> Result<()>` on Store open. Plugins owns `src/plugins.rs`, plugin examples and tests. Peers/distribution owns `src/peers.rs`, `README.md`, `AGENTS.md`, `docs/architecture.md`, `docs/pilot.md`, `examples/`, `scripts/` and peer tests. Do not edit another owner's files without coordinating.

## Core records

Charter: id, objective, absolute repo, actions (default implement/test/publish_pr/merge_green/recovery/cleanup/spawn/message), production_requires_approval (always true for v0.1), active, max_delegation_depth(default4), job_timeout_secs(default900), min_free_bytes(default2GiB), max_heavy_jobs(default1), optional provider_plugin. Task: id, charter_id, owner, title, parent(optional), status(open/running/blocked/done/cancelled), depth. No task authority widening. `task.create` derives charter/depth from parent. `task.handoff` requires current owner and target acceptance; concrete custody in tasks not model prose. `task.update` requires owner identity in args. Event: id (idempotency key), task_id, issue_key, kind, payload; repeated pending alerts coalesce by task+issue but append facts. Acknowledgment is bound to the observed sequence, preserves newer events. Messages are durable targeted task events, not broadcasts. `delivery.check` requires task, current_head, tested_head, checks_passed; production-triggering merge requires separately recorded approval of exact artifact+environment. It is workflow evidence, not a hard credential sandbox or forge integration.

## Jobs module requirements

Commands `job.start`, `job.status`, `job.list`, `job.cancel`, `job.retry`, `resource.status`. `job.start` args task_id, optional id(idempotency), command(array of executable+args), optional cwd, heavy(bool). Cwd must be within charter repo after canonicalization. Effective charter admission before spawn; forbid automatic unsafe retries; supervisor survives invoking CLI, owns process group, bounded logs, deadline, exit result. Shared per-host resource ledger defaults HOME-independent `$PRIVATEER_RESOURCE_HOME` or `~/.local/state/privateer-host`, test override required. Atomic SQLite admission across homes with resource ownership by job incarnation/PID start identity; no reservation release merely because wrapper died. Preserve orphan process capacity for explicit recovery. Startup and cancellation races must not hit unrelated PIDs. Production jobs require exact approval via core; v0.1 job runner can restrict action to ordinary task work and refuse production selector. No arbitrary privileged sandbox claims.

## Plugin requirements

Optional executable JSON-lines protocol for harness/provider integrations. Core has no ZAI/GLM/Philip/endpoints/provider names. Personal gateway is an optional `gateway-pi` example plugin using private config with endpoint/provider/model; actual Pi config endpoint must match before invocation. No fallback outside configured route. Support generic `plugin.validate`, `plugin.command` producing argv+environment *names* rather than values, and `agent.brief` lean task/charter instructions. Native adapter examples for Codex and Pi, no live inference in tests. Plugins get minimal task context and cannot change charter. Prefer explicit argv/stdio boundary, no shell eval.

## Peer requirements

`peer.put`, `peer.list`, `peer.call`: named SSH peer executable/home configuration, safe argv not shell interpolation, bounded request timeout and max response, caller receives same structured envelope as local RPC. Peer is a transport address, not a superior role. Native SSH authenticates; no bespoke credential store. First pilot one conversational role and two peers, direct task messages and shared outcome owner, survives killed coordination session/repeated events. Temporary isolated homes only. Route model jobs through plugin API. Tests and CLI canary demonstrate core first; do not claim full native agent autonomy until exercised.
