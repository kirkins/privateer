# Desk subscription exposure: local-owner contract proposal

## Status and decision needed

**Contract only; no commands, tools, migration or deployment are implemented by this document.** This plan targets a scoped v2 MCP door on `beta`, with the explicitly agreed desk also on `beta`, at generation 1. For a linked example, `alpha -> beta` means that `alpha` calls `beta`; `alpha` supplies push intake and `beta` supplies local intake. `gamma` is an optional additional directly connected source. These names are fictional.

Read this with [door mail coverage](door-mail-coverage.md), especially §§3–7, and [the front-door subscription contract](mcp-front-door.md#5-cross-machine-mail-away-routing-and-duplicate-policy). Those contracts remain authoritative until a reviewed amendment is accepted. This proposal does **not** declare roadmap PRs 4–7 complete.

Recommendation: ship an explicitly enabled, **independent raw-mail pull subscription**, served only by the door host's certified local desk. Start from conservative retained-history replay, not an imported selected-mailbox/dashboard cursor. Do not expose aggregate waiting, held classification, digest or subscription presence yet. Do not implement a remote reader route, owner move or failover to make this case work.

**This is a scope reduction requiring approval, not an engineering shortcut around required gates.** Roadmap §6 puts generation-changing handoff (PR 4), away/digest integration (PR 5) and cursor/state migration (PR 6) before adapter exposure (PR 7). The full phase also requires cross-machine admission and handoff validation. The proposed local raw-only milestone would expose a subset before those full-phase gates pass. Decisions 1–3 below must explicitly authorize that amendment; otherwise retain the original ordering and expose nothing new. Source completeness, generation fencing, current-grant admission, explicit domain selection, privacy, bounds and real adapter/subprocess validation are **not** waived.

### Engine limits to preserve and disclose

- 16 subscriptions per domain; paused live readers still occupy capacity. Terminal readers can be retired transactionally; no eviction of live custody.
- Two snapshots per subscription, at most 96 observations and 16 MiB each; one-hour snapshot lifetime. Page limit 1–50 snapshot positions and 192 KiB **engine** serialized result. The final public/core framing must also be measured and bounded; adding provenance/schema fields cannot silently overrun that limit.
- 256 outstanding sparse refs, including sparse acknowledgments. Pending observations survive projection changes and snapshot expiry.
- 128 receipt slots shared by reservations and outcomes. Unused standalone reservations last 24 hours; committed outcomes last one hour after commit or the issuing snapshot's saved expiry, whichever is later. Identical retries do not extend committed receipts.
- Pull freezes a lowest ordered prefix. A limited snapshot has `complete:false`, retry `pull_after_ack`; null continuation finishes that snapshot only. Ack represented pages, then issue a new pull to obtain later eligible observations.
- Thread starts at the newest bounded tail window, ascending within a window; a terminal continuation requests an independently frozen older window. A limited window has `thread_continue`. Windows are not one history-wide simultaneous snapshot.
- Expired/forged/wrong-operation/anchor/visibility/manifest/generation continuations refuse; never silently restart. Reads issue refs but never implicitly ack. Oversized items refuse rather than disappear.
- These are materialization/custody bounds, not constant SQL work or a hard latency guarantee. Large one-row pages can exhaust receipt throughput at roughly 128 rows/hour with no other pressure; retained outcomes cannot be evicted to advertise unlimited catch-up.

## 2. Minimal path and the deferred roadmap gates

The local path is MCP HTTP request → scoped v2 credential admission → operator-enabled door/domain binding → certified local owner check → subscription engine transaction → **credential release recheck** → structured MCP response. Source ingestion remains independent idle/contact work. No transaction spans a network call; no new machine RPC is needed for this case.

The bridge resolves the expected owner from the configured certified placement, never from plugin arguments. Require generation 1 and the same pinned owner/incarnation and manifest revision/hash at enable and at each operation. A changed, pending or restored placement makes the exposure unavailable; it does not reopen against a successor or infer `here`. The engine's internal conservative reopen against a newly certified owner is **not** authority to implement that public behavior.

## 3. Proposed operator and client surface

All names below are **proposed**, including operator commands. New public inputs are closed objects (`additionalProperties:false`); the core validates independently of Python. Reject reserved identity/provenance fields at every nesting level. No arbitrary peers, routes, paths, SQL, grant IDs, owner tuples, source manifests or client high-water marks.

### 3.1 Operator opt-in, not grant authority

Add owner/operator-only core commands, with explicit CLI argument validation and `ACCEPTED` entries:

| Proposed command | Closed arguments | Meaning |
| --- | --- | --- |
| `door.desk.enable` | `{door, domain, mode:"fresh_replay"}` (all required) | Validate registered scoped v2 door and exact active local generation-1 placement, then persist domain/owner/incarnation, manifest revision/hash and fresh-replay consent. No inferred default domain; no placement, grant expansion, cursor import or intake repair. Identical enable is idempotent; conflicting binding refuses. |
| `door.desk.status` | `{door}` | Operator-only enabled/disabled state, pinned binding, readiness/refusal reason and legacy-fence/migration warning. Do not trigger source enrollment, remote reads or capability expansion. |
| `door.desk.disable` | `{door}` | Stop new subscription admission/release; retain reader custody/state. Re-enable only the identical binding resumes that state. A different domain/owner needs a separately reviewed migration/reset protocol, not disable/re-enable. |

Use normal local operator dispatch/lifecycle policy, not a delegated `fleet:admin` tool or machine gateway verb. No grant can invoke these commands, choose its own domain or alter freshness. Persist configuration in core-owned registry state, not plugin TOML. Serialize enable/disable with admission/state changes; recheck enablement at release. Existing registration/start and grant-consent commands stay unchanged.

### 3.2 Scoped v2 commands and MCP tools

All six raw tools require **`mail:read`**, not `fleet:read` and not `captain:presence`. There is no narrower existing mail-delivery scope; do not add a new scope or expand any grant implicitly. Coverage under `mail:read` uses only opaque visible source handles, not inventory. Optional inventory remains `fleet:read` and is not needed in this milestone.

| MCP tool | Core command | Arguments |
| --- | --- | --- |
| `desk_subscription_open` | `desk.subscription.open` | `{}`; domain comes exclusively from operator configuration. Opens or returns this door/grant's durable reader; no ack. |
| `desk_subscription_resume` | `desk.subscription.resume` | `{subscription}`; recovers state and durable snapshot start tokens, never accepts a cursor. |
| `desk_subscription_pull` | `desk.subscription.pull` | `{subscription, limit?, continuation?}`; default limit 50. Returns authorized unacknowledged projection/pending observations, including outgoing captain conversations. |
| `desk_subscription_show` | `desk.subscription.show` | `{subscription, origin}`; exact retained authorized origin lookup, no implicit ack. |
| `desk_subscription_thread` | `desk.subscription.thread` | `{subscription, origin, limit?, continuation?}`; origin is the exact thread anchor from a served result, with engine window semantics. |
| `desk_subscription_ack` | `desk.subscription.ack` | `{subscription, ack_key, refs}`; all required. Server-issued batch key and actually carried raw refs only. |

`subscription` is an opaque UUID handle, not authority. `origin` is the closed `{core, mailbox, id}` identity already used by the engine: canonical UUIDs for core and mailbox, and the runtime's validated mail identifier. Never interpret core as an RPC destination. `limit` is an integer 1–50; continuation is a nonempty opaque string capped at 256 bytes. `ack_key` and each ref are nonempty opaque ASCII strings capped at 64 bytes; refs has 1–256 entries, with core sorting/deduplication before whole-batch validation. UUID handles have a 36-character canonical format. Mail IDs and operator door/domain identifiers use the existing core identifier rule: 1–160 ASCII letters, digits or `-_.:@`; mirror that length and character rule in the MCP schema.

Do **not** call the server-issued key `idempotency_key`: scoped admission currently strips that field into the generic write replay layer. The desk ledger already owns ack replay. No second receipt cache, client-generated key substitute, cross-generation translation or implicit ack retry. A page key binds one normalized batch: if selecting only part of a page, use a new server key from open/resume for a later distinct batch. Explain this in tool descriptions.

Successful public payloads use `schema:"desk.subscription.v1"`, `subscription`, `incarnation`, and `coverage`. Open/resume return `ack_key` and bounded `pending_snapshots:[{operation,anchor,continuation}]`. Page operations return `items:[{ref,origin,mail,state}]`, `continuation` (string or null) and `ack_key`. Ack returns `acknowledged` and `operation_complete:true`; input domain coverage is still separately dated/possibly incomplete. Core provenance is runtime-authored. The final serialized public payload, including that wrapper and provenance, must fit 192 KiB; reserve wrapper space before engine serving rather than reject an already committed page as oversized afterward. MCP transport framing has its own separately bounded overhead. Do not claim a raw ack closes a request, acknowledges the dashboard, or delivers any digest.

Each call, including open/resume/continuation/ack, resolves the actual bearer credential; the engine then verifies exact current local grant authority in its writer transaction. Recheck the credential, visibility revision and exposure binding before returning any protected result. No cached grant authority, unattended polling or SSE push. A revoke committed before engine admission prevents serving/ack changes; one committed after admission may hide the response but cannot undo committed served rows or acks. Release loss after an ack is `outcome_unknown`, not proof that nothing changed. Retry only the identical key/batch while retained.

### 3.3 Discovery, rendering and refusals

Extend scoped `capabilities` with a versioned, safe desk feature descriptor only for an enabled, admitted mail reader. Proposed shape: `desk_subscriptions:{schema:"desk.subscription-capability.v1",mode:"local_raw",operations:["open","resume","pull","show","thread","ack"],remote_owner:false,moves:false,waiting:false,presence:false,digests:false}`. It reveals no placement/domain or source inventory. A feature descriptor is not stored authority: every tool call repeats core admission. Tools/list filters by **both** `mail:read` and the descriptor. Hidden/non-enabled tools remain non-disclosing not-found on guessing; authentication failures retain normal OAuth challenges. Trusted v1 cannot acquire these commands by announcing v2.

Do not flip the legacy/global `subscriptions:false` diagnostic to an unqualified true. Keep selected-mailbox/local diagnostics scoped to their old surfaces; add the new qualified feature separately. Availability failures do not remove the operator's recorded opt-in or switch mail tools.

Preserve `coverage.v1` on every admitted new result, including failures, or use a closed non-disclosing refusal when coverage cannot safely be established. Snapshot coverage is frozen and dated, not recomputed as current on continuation. Render:

- `scope:"desk-domain"`, domain, visible opaque sources, source states/checkpoints, observation time, snapshot and allowed owner/revision fields exactly as admitted. Named-ship readers retain `complete:false`, null owner/revision and no hidden counts/topology.
- “As of last source contacts,” showing each available barrier mode, desk-measured `received_at`, `age_ms`, and the operator's `max_source_age_ms` (default 900000). Even collect/local barriers here are dated evidence; a pull creates no on-demand contact. Replay/import cannot refresh freshness.
- Omissions and history/unreadable/backpressure/unsupported gaps, and each retry action. Empty partial results say coverage is incomplete, never “nothing needs you.” Missing/malformed coverage stays incomplete; Python cannot manufacture proof.
- Continuation and `pull_after_ack`/`thread_continue` instructions separately from `coverage.complete`. A complete source vector does not mean drained inbox, exhausted history or completed work.

The bridge must normalize the internal engine's string-error envelope into a closed public error object **without losing coverage**. The current adapter's generic not-found collapse is insufficient. Proposed public error schema is `{code, message}` with optional allowlisted value-free `retry`/`hint`, alongside `coverage` when safe; no raw exception text. Preserve these outcomes:

| Condition | Admitted client result | Operator detail / recovery boundary |
| --- | --- | --- |
| No active placement, pending acceptance or restore mismatch | `unavailable`, incomplete/unknown-domain coverage; no inferred mailbox | Distinguish absent/pending/restore guard in operator status only. Restore needs exact certified recovery, never re-bootstrap. Unknown and wholly hidden domains have the same client refusal. |
| Owner is remote, including callable remote owner | `unavailable` with fixed wording **“unsupported read direction / incomplete feature”** where safe; no local fallback | Local-owner exposure only; remote-owner admission/transport remains missing. Do not imply retrying will implement it. |
| Owner is reverse-only | Same closed unavailable refusal and wording; no spool or third-machine relay | Operator can diagnose direction. Existing selected-mailbox hints remain separate. No automatic relocation/link/route proposal or execution. |
| `oversized_item` | Preserve code, incomplete coverage and fixed “item cannot fit; nothing skipped” wording | No truncated successful item or fabricated safe handle. Larger-body retrieval is separate work. Do not auto-ack the obstacle. |
| `backpressure` | Preserve code; pending facts retained | Ack already served refs using a valid key if possible; otherwise wait for explicit snapshot/receipt expiry or operator diagnosis. No eviction, reset or increased admission floor workaround. |
| Expired, forged, stale, wrong-anchor or wrong-reader continuation | `stale_or_unknown`, incomplete coverage | Resume for retained start tokens; otherwise explicitly begin a new read, which may replay. Never automatically discard the token and claim seamless continuation. |
| Wrong-kind/reader/generation ref, invalid mixed batch | `invalid_ack` (or non-disclosing stale refusal), no partial batch mutation | Selected-mailbox/digest refs cannot become desk refs. Old refs cannot acknowledge any replacement incarnation. |
| Expired/unknown receipt or key | `stale_or_unknown`, never fabricated ack success | Retained identical retry only; after expiry recover pending mail with fresh served refs/key. No assertion that an uncertain old ack failed. |
| Grant/credential/enablement changes before release; lost output or uncertain commit | Withhold data; normal auth refusal for reads, `outcome_unknown` for an ack that may have committed | Served custody survives lost pages. Retry identical ack arguments/key, never substitute a new key merely to escape uncertainty. |

Specific owner/direction diagnostics must not disclose hidden placement. If the grant cannot safely distinguish them, use the same generic unavailable envelope; the fixed hint contains no peer names or paths. The internal engine currently maps many errors, including owner/SQL failures, to `unavailable`. The bridge/engine boundary needs explicit typed pre-effect versus uncertain-commit classification for exposed acks; mapping every failure to a definite no-effect denial would be incorrect.

### 3.4 Coexistence with today's tools

`mail_inbox`, `mail_show`, `mail_thread`, `mail_ack` retain selected-mailbox identities, limits, refs, error semantics and coverage. No overloaded `ship`, `scope` or implicit default changes them into aggregate tools. `fleet_waiting` stays local under its existing `fleet:read` contract, including its legacy body behavior; it is not an aggregate all-clear. New raw tools may duplicate those tools' mail intentionally. Their acknowledgments never advance selected-mailbox, v1, dashboard, digest or another grant/door's progress.

No new aggregate waiting tool in this milestone. When implemented later, metadata-only waiting requires `fleet:read`, omits body/payload and sensitive derived text; body opt-in additionally requires `mail:read`, with an explicit migration notice. That is the captain's existing policy, not an open question or permission to expose bodies under `fleet:read` alone. Current Python tool filtering assumes one scope per tool; any later multi-scope surface needs independent core and adapter tests.

Existing away/held/digest operations are **not** rebranded subscription integration. Placement's legacy writer fence remains in force until real migration. Do not unfreeze those writers, import pending summaries as delivered, or make a successful operation-only presence result imply domain coverage. Ordinary sends and replies keep native authorization, recipient binding and away-preserving scoped-send rules; a subscription copy confers no new answer authority.
