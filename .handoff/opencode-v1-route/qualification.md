# OpenCode V1 qualification and route backoff

Manifest: `bundled:opencode` launches `native_launch.py opencode`. Verified in `plugins/native.py`: allowed options are `model`, `effort`, `resume`, and `mode`; provider is not allowed. Headless command is `opencode run --format json --dir <repo> --model <model> [--variant <effort>] -- <prompt>`. Thus the exact model values are `space-bunny-free` for `opencode/space-bunny-free` and `deepseek-v4.1-flash` for the first mate's `opencode-go/deepseek-v4.1-flash`; OpenCode V1 does not accept a provider option. Job route records are the adapter-level route `opencode/-/<model>`.

Qualification jobs `d886a3f5-dca1-48b9-8af3-bdde4918d284` (paid) and `26b7f4aa-a3ce-484e-89b7-b13f0d73de1d` (free) were launched through `agent.start` with `timeout_secs: 90` requested; job metadata recorded the charter default of 3600 seconds. Both nevertheless ended after about two seconds with exit 1. The paid route was recorded as `opencode/-/deepseek-v4.1-flash`; the free route was `opencode/-/space-bunny-free`. Both emitted a JSON `type:error` with `name:UnknownError`, message `Unexpected server error. Check server logs for details.` and distinct `ref` values. No success event, allowance exhaustion, 429, reset, or retry-after hint was observed. Therefore a successful V1 output shape and real quota exhaustion remain unqualified; the error appears to be an upstream/server failure, not evidence about allowance behavior.

Implementation classifies explicit free allowance and quota exhaustion separately from ordinary 429/503/529/rate-limit/overload signals. It honors numeric retry-after/reset hints and relative `resets in`/`try again in` hints; absent a hint, it records a 24-hour backoff. Ordinary throttle doubling remains capped at 15 minutes. The existing host-ledger refusal path and route keys are unchanged.
